# React dashboard migration

The crawler service remains Express, JavaScript, and MySQL-backed. Only the
dashboard is being migrated to React + TypeScript + Vite.

## Safety model

- The existing dashboard at `/` remains the supported production interface.
- The React build is served independently at `/next/`.
- Both interfaces use the same per-tab session key (`omnicrawl-tab-session`),
  so moving between them in the same tab resumes the same crawl rather than
  starting another one.
- No API route, engine, persistence schema, or existing dashboard asset is
  removed during the migration.
- The React bundle is committed under `src/public/next/` for the current
  Hostinger deployment model, which serves static application files directly.

## Commands

```bash
npm run client:dev
npm run client:build
npx tsc --noEmit
npm test
```

`client:dev` is for the React UI only. Run `npm start` in another terminal to
serve the crawler API. The production preview is generated by `client:build`
and can be reached through Express at `/next/`.

## Delivered in the first slice

- typed crawler API client and crawler domain types;
- a reusable live-state hook with SSE and a 2-second polling fallback;
- target/scope, page-limit, and advanced execution controls;
- start, pause, resume, abort, clear/reset, capacity, and engine status;
- summary metrics, pages search/filtering, page inspection, and all exports.
- discovered-links table backed by the canonical crawler link records, with
  internal/external/content-area/status/nofollow filters, column sorting,
  pagination, and link inspection.

## Remaining slices

1. Resources inventory with status/type filters and sorting.
2. SEO issues, including duplicate-content grouping and export parity.
3. Extracted-content explorer, crawl history, and final accessibility/layout QA.
4. Move the React build from `/next/` to `/`, retain the legacy dashboard for
   one release as a rollback route, then retire it only after acceptance.

The API contract stays stable across each slice. A deployment happens only as
an agreed batch once the React dashboard has feature parity.
